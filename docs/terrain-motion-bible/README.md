# TERRAIN Component & Motion Bible

## Purpose

This review surface maps the current DanceLab runtime and approved TERRAIN direction into one implementation ledger:

`code -> source of truth -> trigger -> UI behavior -> motion -> timing -> owner -> independent QA voice`

It is a specification and review tool. It does not replace runtime tests and does not claim that planned components are implemented.

## Open

Open `index.html` directly in a browser. No build step or server is required.

## Status vocabulary

- `Existing`: current runtime foundation is present.
- `Adapt`: current runtime exists but requires TERRAIN UI adaptation.
- `Planned`: approved contract without a completed runtime implementation.
- `Deferred`: intentionally blocked until a real data source or prerequisite exists.

## Review protocol

1. Junior supplies reproducible evidence.
2. Mid synthesizes the finding and implementation impact.
3. Engineering, Product and Motion challenge the contract together.
4. Senior owners make and record the decision.
5. Unresolved dissent remains visible instead of being silently discarded.
